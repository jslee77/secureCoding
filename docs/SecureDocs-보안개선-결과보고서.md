# SecureDocs 보안 개선 결과 보고서

> SecureDocs의 보안 결함 23건과 후속 점검에서 찾은 2건(R-01, R-03)을 코드에서 직접 수정하고, 공격을 다시 재현해 차단 여부를 확인한 결과입니다.
> 항목별 원인과 수정 코드는 [보안 취약점 개선 내역](./SecureDocs-보안취약점-개선내역.md)을 참고하세요.

| 항목 | 내용 |
|---|---|
| 작성일 | 2026-09-21 |
| 대상 | `app/` (Flask API), `static/app.js` (프론트엔드), 설정·스키마·의존성 |
| 검증 방법 | pytest 회귀 테스트(`tests/`) — 테스트마다 임시 DB를 새로 시드하고 Flask 테스트 클라이언트로 공격을 재현. 프로젝트 Docker 이미지(`python:3.12-slim`)에서 실행 |

## 1. 요약

| 지표 | 결과 |
|---|---|
| 조치한 취약점 | **23건** (Critical 7 · High 11 · Medium 5) + 후속 점검 2건 (R-01, R-03) |
| 회귀 테스트 | **56개 중 56개 통과** (공격 차단 + 정상 동작) |
| 기존 기능 | 로그인 · 문서 CRUD · 공유 · 댓글 · 첨부 · JSON 백업 · 관리자 기능 정상 |
| 남은 과제 | 코드 수준 5건 · 기능 결함 3건 · 운영 준비 항목 (4장) |

**결론:** 확인된 취약점은 모두 막혔고, 이 취약점들을 이어 붙이던 공격 사슬(경로 조작 → 시크릿 유출 → 토큰 위조 → 관리자 장악)도 끊겼습니다.
다만 운영 환경에 올리려면 4장의 잔여 과제와 5장의 배포 체크리스트를 먼저 처리해야 합니다.

## 4. 남은 과제

검증 과정에서 함께 확인한 사항입니다. 그중 R-01과 R-03은 이번에 조치했고, 나머지는 알려진 공격 경로를 다시 여는 수준은 아니지만 운영 전에 처리하는 것을 권장합니다.

### 4-1. 보안 (코드 수준)

| ID | 내용 | 영향 | 권장 조치 | 우선순위 |
|---|---|---|---|---|
| ~~R-01~~ | 업로드 폴더가 `static/uploads/`에 있어 `/static/uploads/<저장명>`으로 **인증 없이** 파일 제공 | 저장명을 아는 사람은 문서 권한이 회수된 뒤에도 접근 가능 | ✅ **조치 완료** — `instance/uploads/`로 이동 | — |
| R-02 | 회원가입이 중복 아이디에 `409` 반환 | 아이디 존재 여부 확인 가능 (레이트리밋으로 완화) | 가입 응답 일반화 또는 이메일 인증 기반 가입 | 중간 |
| ~~R-03~~ | 비밀번호 변경 시 **현재 비밀번호 확인 없음**, 비밀번호 정책 없음 | 탈취된 세션으로 비밀번호까지 바꿔 계정 장악 | ✅ **조치 완료** — 현재 비밀번호 재확인, 가입·변경 시 8자 이상 (유출 비밀번호 검사는 추후 과제) | — |
| R-04 | JWT 폐기 수단 없음 — 로그아웃은 쿠키만 삭제 | 탈취된 토큰이 만료(60분)까지 유효 | 토큰 `jti` 차단 목록 또는 짧은 수명 + 리프레시 토큰 | 중간 |
| R-05 | CSP에 `script-src 'unsafe-inline'` | XSS 방어가 입력 정제·출력 이스케이프에 의존 | 인라인 `onclick`(index.html 12곳 · app.js 4곳) 제거 후 nonce 기반 CSP | 중간 |
| R-06 | CSRF 토큰 없음 | `SameSite=Lax`에 의존 (구형 브라우저·서브도메인 공격에 취약) | 상태 변경 요청에 CSRF 토큰 또는 `Authorization` 헤더 전용 인증 | 낮음 |
| R-07 | SSRF 검사 시점과 요청 시점의 DNS 해석이 분리 | DNS 리바인딩 이론상 가능 (허용목록으로 완화) | 검증한 IP로 직접 연결하거나 egress 프록시 사용 | 낮음 |

### 4-2. 기능 결함 (보안 외)

| 내용 | 비고 |
|---|---|
| PDF 내보내기가 동작하지 않음 | 이미지에 LibreOffice(`soffice`)가 없고, 변환할 원본 파일도 생성하지 않음. 처리되지 않은 예외(500) 대신 이제 `503`과 안내 메시지를 반환 |
| 비밀번호 재설정 확인 API 없음 | 토큰 발급만 구현(`/api/profile/reset-request`), 토큰으로 재설정하는 단계가 없음 |
| `/api/auth/refresh`가 저장되지 않는 임의 값을 반환 | 데모용 스텁 |

### 4-3. 운영 준비

| 영역 | 현재 | 권장 |
|---|---|---|
| 웹 서버 | Flask 개발 서버(`app.run`) | gunicorn 등 WSGI 서버 + 리버스 프록시 |
| 컨테이너 | root 실행, 소스 볼륨 마운트 | 비루트 사용자, 이미지에 소스 고정 |
| HTTPS | 미적용, HSTS 없음 | TLS 종료 + HSTS, 프록시 뒤라면 `ProxyFix`로 `Secure` 쿠키·클라이언트 IP 보정 |
| 레이트리밋 | 메모리 저장소(프로세스별) | Redis 등 공유 저장소 |
| 시크릿 | 환경변수 또는 `instance/secret.key` | KMS / Vault, 주기적 교체 |
| 토큰 서명 | HS256 (대칭키) | 서비스가 늘어나면 RS256 / EdDSA |
| 데이터베이스 | SQLite | 동시 사용자가 있으면 PostgreSQL 등 |
| 공급망 | 의존성 고정만 | CI에 `pip-audit` 등 취약점 스캔 |

## 5. 운영 배포 체크리스트

코드 취약점은 조치됐지만, **저장소에 포함된 데모 데이터는 공개 환경에 그대로 두면 안 됩니다.**

- [ ] **데모 계정 제거** — `app/seed.py`의 `admin/admin123` 등 공개된 비밀번호 계정을 삭제하거나, 시드를 운영에서 실행하지 않기 (`Dockerfile`이 빌드 시 시드를 실행함)
- [ ] **데모 데이터 제거** — 시드가 만드는 `instance/DO_NOT_SHARE.txt`, `instance/rce_flag.txt`, 관리자 API의 고정 응답값(`/api/admin/secret`, `/api/tools/internal/metadata`)
- [ ] **자가채점 기능 제거** — `/flags` 페이지와 `/api/flags/*` (`app/flags.py`, `static/flags.html`)
- [ ] **시크릿 주입** — `JWT_SECRET`, `SECRET_KEY`, `DATA_KEY`를 환경변수로 전달 (`DATA_KEY`는 Fernet 키: `python -c "from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())"`)
- [ ] **4-3 운영 준비** — WSGI 서버, 비루트 컨테이너, HTTPS

## 6. 재현 방법

```bash
# 이미지 빌드 및 실행
docker compose up --build        # http://localhost:5000

# DB를 초기 데이터로 되돌리기
docker compose exec securedocs python -m app.seed
```

- 업로드 폴더가 `static/uploads/`에서 `instance/uploads/`로 바뀌었습니다. 기존 환경에 `static/uploads/`가 남아 있다면 삭제하세요(정적 경로로 계속 제공됩니다). 이전 첨부를 유지하려면 파일을 `instance/uploads/`로 옮기면 됩니다.
- 시크릿은 최초 기동 시 `instance/secret.key`에 생성되며, 재시작해도 유지됩니다(발급된 JWT 계속 유효).
- DB는 argon2id 해시와 Fernet 암호문으로 시드됩니다(사용자 5명 · 문서 7건).
- `/flags` 자가채점 페이지는 남아 있지만, 플래그를 얻던 경로가 모두 막혀 **15개 중 어느 것도 더 이상 획득할 수 없습니다.**
