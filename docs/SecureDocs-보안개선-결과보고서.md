# SecureDocs 보안 개선 결과 보고서

작성/갱신: 2026-09-22 · 대상: 현재 소스, 테스트, 설정, 배포 예제

초기 V-01~V-23, 후속 R-01~R-10에 이어 재점검 S-01~S-11을 수정했습니다. **이번에 진단한 11개 항목의 코드 조치는 완료했고, 아래 회귀 테스트로 검증했습니다.** 이것이 모든 가능한 취약점의 부재나 운영 배포 인증을 의미하지는 않습니다.

과거의 “코드 결함 없음 / 운영 인프라만 남음”이라는 표현은 철회합니다. 초기 진단은 [최초 취약점 분석](SecureDocs-최초-취약점-분석.md), 수정 원리는 [개선 내역](SecureDocs-보안취약점-개선내역.md), 수정 전 재현 증거는 [재점검 기록](SecureDocs-시큐어코딩-재점검-2026-09-22.md)에 있습니다.

### bandit 정적 분석 — 초기 10건 분류

파이썬 정적 보안 분석기 bandit을 `app/` 전체에 적용했습니다. 최초 스캔의 10건(Medium 2·Low 8)은 실제 취약점이 아니라 **오탐 또는 이미 방어된 설계 결정**이었고, 각 지점에 근거를 단 `# nosec <ID>` 주석으로 억제했습니다. 이후 스캔은 0건이며, CI가 앞으로 새로 생기는 지적을 차단합니다.

| 규칙 | 위치 | 판정 | 근거 |
|---|---|---|---|
| B608 (SQL) | `documents.py` · `update_document`/`delete_document` | 오탐 | 컬럼·테이블명은 고정 화이트리스트, 값은 파라미터 바인딩 |
| B603 (subprocess) | `files.py` · 업로드 검증, `tools.py` · PDF 변환 | 설계상 안전 | `shell=False` + 인자 리스트, argv에 사용자 입력 없음 |
| B404 (import subprocess) | `files.py`, `tools.py` | 정보성 | 위 두 용도로만 사용 |
| B105 (hardcoded password) | `validation.py` · `STRING_LIMITS` | 오탐 | 길이 제한 dict의 키 이름(`password` 등)일 뿐 시크릿 아님 |

> `# nosec`는 규칙 ID를 명시하므로, 같은 줄에 **다른 종류의** 새 지적이 생기면 그대로 검출됩니다.

CI는 Python 3.12와 Node 24에서 테스트하고 의존성 감사를 수행하도록 설정했습니다. 위 수치는 로컬에서 실제 수행한 결과입니다. CI의 원격 실행 결과와 동일하다고 미리 가정하지 않습니다. Docker 데몬이 실행 중이지 않아 실제 Linux 이미지·gunicorn·TLS 프록시·브라우저 전체 흐름은 이번 실행에서 검증하지 못했습니다. 기존 SSRF와 PDF 내보내기 테스트는 모의 네트워크/변환기를 사용합니다. 새 업로드 검사는 실제 Pillow·pypdf 파서를 실행합니다.

추가로 refresh 토큰 회전도 원자화했습니다. 기본 교육용 API는 비활성화했고, 정적 파일을 명시적 허용목록으로 제한해 구버전 `static/uploads/` 잔류 파일의 직접 노출을 차단했습니다. 공유받은 문서도 목록·검색에 표시하며, 화면에는 페이지 이동을 제공합니다. Compose는 루프백에 바인딩하고 기본 gunicorn 워커는 memory 레이트리밋에 맞게 1개로 변경했습니다.

텍스트는 UTF-8이며 NUL 등 불필요한 제어문자를 거부합니다. 파일 파싱은 **악성코드 검사나 PDF의 능동 콘텐츠 제거(CDR)가 아닙니다.** 다운로드는 attachment와 nosniff를 유지합니다. 기본값은 예제 기준이며 실제 업무량·위험도에 따라 설정과 운영 자원 한도를 함께 조정해야 합니다.

## 4. 기존 데이터의 업그레이드

1. 서비스 중지 후 DB·업로드·암호화 키를 **같은 시점의 백업**으로 보존합니다. `python -m app.seed`는 초기화 명령이므로 운영 업그레이드에 사용하지 않습니다.
2. 시크릿 파일은 앱 실행 사용자 소유, 권한 `0600`이어야 합니다. 손상·누락 키를 새로 만들어 기존 암호문을 계속 사용하려 하지 말고 기존 키를 복구합니다. 기존 파일이 없는 신규 설치에서만 자동 생성합니다.
3. 앱은 새 컬럼·삭제 큐·인덱스를 생성합니다. 중복 공유는 **가장 큰 id(최근 요청)** 한 행을 남기므로 기존의 읽기 전용 변경 의도가 반영됩니다. 기존 첨부의 실제 파일 크기는 허용된 업로드 폴더에서 계산해 저장 한도에 포함합니다.
4. 이전 버전의 `static/uploads/`는 더 이상 HTTP로 제공하지 않습니다. 파일을 `instance/uploads/`로 옮기고 DB 매핑·소유권을 확인하는 작업은 백업 후 별도로 수행합니다. 구버전 XOR 암호문의 Fernet 변환이나 외부 키 교체도 자동 수행하지 않습니다.
5. 이미 남아 있는 고아 파일/행은 이번 삭제 API의 큐에 자동 등록되지 않습니다. 기존 저장소와 DB를 대조해 별도 정리합니다. 진행 중 프로세스 강제 종료까지 포함한 파일 시스템·DB의 완전한 원자성은 보장하지 않습니다.
6. 파일 삭제 실패는 `pending_file_deletions`에 남습니다. 앱 시작 때 재시도하며, 운영에서는 `flask --app 'app:create_app()' files cleanup`을 주기적으로 실행하고 남은 작업 수를 확인합니다. 삭제된 파일의 백업 보존기간은 별도 정책입니다.

## 5. 운영 배포에서 남는 작업

- 공개된 데모 계정이 있는 볼륨을 운영에 재사용하지 않습니다. `SEED_DEMO_DATA` 해제는 이미 존재하는 계정을 삭제하지 않습니다.
- `JWT_SECRET`·`SECRET_KEY`는 최소 32바이트의 강한 난수, `DATA_KEY`는 유효한 Fernet 키로 주입합니다. 키·데이터 백업, 복구 시험, 키 회전을 운영 절차로 관리합니다.
- TLS 프록시, HTTP→HTTPS 전환, `COOKIE_SECURE=1`, 실제 프록시 수에 맞는 `TRUST_PROXY_HOPS`, 백엔드 직접 접근 차단을 적용합니다.
- 다중 워커/서버로 확장하면 Redis 등 공유 레이트리밋 저장소를 구성합니다. 기본 memory 카운터는 재시작하면 초기화됩니다. 이번에 다중 워커 Redis 통합 테스트를 수행한 것은 아닙니다.
- `ENABLE_TRAINING_ROUTES`는 기본 0입니다. 운영에서는 1로 설정하지 않습니다.
- `deliver_reset_token`은 발송 연동 지점이며 현재 로그만 기록합니다. 실제 계정 소유 확인 채널을 연결해야 복구 기능이 완성됩니다. 변경 가능한 미검증 이메일을 그대로 복구 대상으로 연결하지 않습니다.
- LibreOffice는 기본 이미지에 없습니다. PDF 변환이 필요하면 별도 자원 제한·네트워크 격리·동시성 제한을 갖춘 실행환경을 구성하고 실제 변환을 검증합니다. 변환기 미설치 시 `503`입니다.
- 개인정보 수집 최소화, 로그 회전/보존, 백업 파기, 파일 악성코드 검사 정책을 운영 요구에 맞춥니다. 사용되지 않는 API 토큰은 현재 인증 수단이 아니며, 향후 도입 시 해시 저장·권한 범위·만료·폐기를 설계해야 합니다.
- 직접 의존성은 버전 고정돼 있지만 전이 의존성 lock/hash, 이미지 digest, Actions commit pin은 아직 없습니다. 릴리스 재현성 강화와 정기 감사는 후속 공급망 관리 과제입니다.

## 6. 재검증 명령

```bash
pip install -r requirements-dev.txt
python -m pytest -q
node --test tests/frontend.test.cjs
python docs/security-review/probe_security.py
bandit -r app/                                   # 정적 보안 분석 (0건이어야 통과)
pip install pip-audit
pip-audit -r requirements.txt
```

Docker로 실행 중이면 컨테이너 안에서도 동일하게 할 수 있습니다(강사 권장 절차). bandit은 개발 도구라 런타임 이미지에는 없으므로 먼저 설치합니다.

```bash
docker compose exec securedocs pip install bandit
docker compose exec securedocs bandit -r app/
docker compose exec securedocs bandit -r app/ -f html -o /app/bandit-report.html
```

> 생성된 HTML 리포트 예시는 [docs/security-review/bandit-report.html](security-review/bandit-report.html)에 있습니다.

`probe_security.py`는 현재 `tests/test_review_fixes.py`를 실행하고 실패를 종료 코드에 반영합니다. 수정 전의 취약 동작은 `observations-before.jsonl`에만 역사적 증거로 남깁니다. CI가 통과해도 검증하지 않은 배포 조건까지 안전하다고 단정하지 않습니다.
